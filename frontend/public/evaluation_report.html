模型功能: 本系统旨在解决电力数据在长链路流转中产生的质量追溯难题。它创新性地采用“大小模型协同”架构：首先利用小模型处理引擎对多版本数据进行精准比对与风险量化，自动筛选高风险异常项；随后，将量化信息注入大语言模型，由其进行深度的归因推理和逻辑分析，最终自动化生成包含核心发现、原因推测与修正建议的决策支持报告。

优势: 融合了小模型的精准高效与大模型的深度洞察力，实现了端到端的自动化分析流程；相比传统人工追溯，分析效率提升明显；报告内容不仅包含差异，更能提供具备业务价值的归因推测和治理建议，决策支持能力强。

应用场景: 该系统可广泛应用于电力行业的数据质量治理、跨部门数据核对、异常数据成因追溯、业务数据审计等场景，为电力系统的数字化运营和智能化管理提供核心决策支持。

二、系统核心能力评测

系统设计理念概述

本系统旨在应对电力数据链路长、异常追溯困难的挑战。其创新性地采用“大小模型协同”架构：首先，利用以数据分析引擎为核心的“小模型”进行高效、确定性的数据差异比对与风险量化，精准锁定高风险变更点；随后，将这些结构化信息注入“大语言模型”，由其进行深度的归因推理与智能分析，最终自动化生成具有业务洞察的决策支持报告，实现了从“发现问题”到“辅助决策”的全流程智能化。

报告生成质量评测 (基于抽样分析)

通过对系统生成的抽样报告进行评估，大模型在分析任务中展现出卓越的性能。报告质量体现在：
  • 结构化与逻辑性：报告结构清晰，从“高风险识别”到“归因推断”，再到“处置建议”，层层递进，逻辑严谨。
  • 洞察与推理能力：系统不仅能识别数据异常，更能基于数据变化模式推断出如“单位可能混淆”、“数据采集链路疑似中断”等深层次、具有业务价值的潜在原因。
  • 实用性与可操作性：最终产出的“核查建议”与“数据治理建议”具体、可落地，为业务人员提供了清晰的行动指南，充分体现了系统作为决策支持工具的核心价值。

三、资源与环境需求

硬件资源 (服务器)

  • CPU: 基础多核CPU (推荐 4 Cores+)
  • 内存: 建议 > 2GB (处理大数据量时 > 8GB)
  • GPU: 无需本地GPU
  • 存储: > 20GB 可用空间 (用于Docker镜像和数据)

软件与网络环境

  • 部署环境: Docker & Docker Compose
  • 开发依赖: Python 3.9+, Node.js 22.x+
  • 网络需求: 需稳定互联网连接以调用大模型API
  • 可扩展性: 支持通过增加后端服务容器进行水平扩展
